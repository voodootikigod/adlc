# ADLC 1.3 ticket-store compatibility bridge

ADLC 1.3 introduces `@adlc/tickets` and makes one-file-per-ticket storage under
`.adlc/tickets/` the default for newly initialized repositories. The static
`.store.json` manifest never contains ticket IDs, so independent ticket additions
normally merge as independent Git paths.

Existing `.adlc/tickets.json` repositories continue to read and write normally
throughout 1.x. Interactive mutation commands show a representation-only migration
plan and ask `Apply migration? [y/N]`; declining stays on the legacy backend. JSON,
CI, hook, and other non-interactive paths never prompt or migrate. Automation must use
`adlc ticket store migrate --write --yes` explicitly.

Migration requires a clean worktree, imports the legacy archive, verifies active and
archive hashes, records hash-bound evidence, and never stages or commits. Interrupted
transactions require an explicit `--complete` or `--rollback`. Land the repository's
actual storage conversion later as a dedicated, human-reviewed commit.

The compatibility bridge may remain in 1.4 if field evidence requires it. ADLC 2.0
removes normal legacy operation and the old `ADLC_TICKETS`/`--tickets` overrides, while
retaining the legacy migration reader indefinitely.

Operational details are in the [migration guide](../ticket-store-migration.md), with
the decision and security boundaries in [ADR-0010](../adr/0010-sharded-ticket-store.md)
and the [threat model](../ticket-store-threat-model.md).
